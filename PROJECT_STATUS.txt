A. PROJECT OVERVIEW
--------------------------------------------------------------------------------
Project Name:               MoodLens
Project Description:        Real-Time Facial Expression Detection and Privacy-First 
                            Personalized Suggestion Platform.
Core Mission:               Provide edge-computed, privacy-preserving visible facial expression 
                            estimates (happy, sad, angry, fear, disgust, surprise, neutral) 
                            running 100% in-browser via WebAssembly, combined with context-aware, 
                            user-confirmed wellness and lifestyle suggestions. Zero raw facial 
                            images or video streams are ever transmitted to or stored on servers.
Main Technologies:
  - Frontend:               React 18, TypeScript 5.6, Vite 6.4, TailwindCSS 3.4, Zustand 4.5, 
                            Lucide React, Recharts 2.14, Axios
  - Edge Inference & CV:    MediaPipe FaceLandmarker (@mediapipe/tasks-vision 0.10.22), 
                            ONNX Runtime Web 1.18 (WebAssembly SIMD/Threads), HTML5 Canvas
  - Backend:                FastAPI 0.110, Uvicorn, Python 3.9.6, SQLAlchemy 2.0 (Async), 
                            Alembic 1.13, Pydantic v2 (2.5.3), python-jose, bcrypt, SlowAPI, 
                            Structlog
  - Database:               SQLite (dev mode via aiosqlite, moodlens_dev.db), PostgreSQL 15 
                            (production via Docker Compose), Redis 7 (caching/rate-limiting)
  - Machine Learning:       PyTorch 2.1, Torchvision 0.16, MobileNetV3-Large, ONNX 1.15, 
                            ONNXRuntime 1.17, Albumentations, Scikit-learn
Project Architecture:       Decoupled Edge-Cloud Architecture.
                            1. Edge (Browser): Video capture -> FaceLandmarker -> 478 3D landmarks + 
                               52 blendshapes -> Face crop (112x112) -> ONNX MobileNetV3-Large INT8/FP32 
                               -> Probabilities -> Dual-head Fusion -> EMA Temporal Smoother -> State 
                               Machine (VISIBLE, OCCLUDED, NO_FACE, MULTI_FACE).
                            2. Cloud (FastAPI): User authentication, granular GDPR consent management, 
                               session metadata, batch expression events telemetry, action authorization 
                               tokens (60s TTL), trusted contact escalation, model registry.
Current Development Stage:  Stage 4 - System Integration & Hardening (Feature Complete Working System)
Last Updated Date and Time: 2026-11-02 01:25:00 UTC+05:30

Entry 9: Resolve Browser Hang and Tab Crash (Error Code: RESULT_CODE_HUNG)
- Date: 2026-11-05 00:08:00 UTC+05:30
- What was changed:
  1. Identified Root Cause of RESULT_CODE_HUNG:
     - When the ONNX model finished loading mid-session, ExpressionClassifier executed Test-Time Augmentation (TTA) using Promise.all([this.runONNX(tensor), this.runONNX(flippedTensor)]).
     - Running two concurrent session.run calls on a single-threaded WebAssembly runtime caused re-entrancy deadlock in WASM.
     - WebAssembly linear memory was never freed because input/output ort.Tensors were not disposed, causing heap exhaustion and garbage collection freezes.
  2. Implemented Non-Blocking, Memory-Safe ONNX Pipeline:
     - Switched to a single forward pass with runONNXWithTimeout(tensorData, 400), eliminating WASM re-entrancy and halving computation time.
     - Wrapped ONNX execution in try/finally to explicitly dispose input and output tensors (inputTensor.dispose(), results[key].dispose()), stopping WASM heap leaks.
     - Added isInferencing mutex guard preventing overlapping inference calls on the WebAssembly runtime.
  3. Optimized Inference Scheduler & CPU Pressure:
     - Added an adaptive latency tracker to InferenceScheduler: if inference takes > 70ms on slower devices, it throttles the interval to prevent thread starvation.
     - Added a 1500ms watchdog timer auto-releasing isInferenceRunning if an inference frame ever exceeds 1.5s.
     - Preallocated grayBuffer in FaceQualityAssessor to prevent 4KB array allocations inside the loop.
     - Throttled pipeline debug state updates (updatePipelineState) in useExpression.ts from 15 FPS to 10 FPS.

M. KNOWN LIMITATIONS
--------------------------------------------------------------------------------
1. Spotify Web API Client ID: Spotify OAuth integration requires a valid Client ID registered in Spotify 
   Developer Dashboard. In local dev mode without credentials, provider falls back to launching web playlists.
2. Hardware Camera Dependency: Webcam access requires user browser permission grant and physical/virtual 
   camera hardware.
3. Facial Expression vs Internal Emotion: Facial expression estimates are physical visible cues, not a 
   psychological diagnosis. The system explicitly disallows automated emergency escalation without confirmation.
4. Local Dev vs Production Database: Development uses zero-config SQLite (moodlens_dev.db via aiosqlite). 
   PostgreSQL 15 and Redis require starting Docker Compose containers (docker-compose up -d).
